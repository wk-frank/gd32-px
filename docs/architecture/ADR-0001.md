# ADR-0001：基于 PX4 v1.17.0 原生 NuttX 体系移植至 GD32H757ZMT6

- **状态**：已采纳（M0 基线决策）
- **日期**：2026-11-13
- **目标平台**：GD32H757ZMT6（Arm Cortex-M7，最高 600 MHz，3840 KB Flash，1024 KB SRAM，LQFP144）
- **软件基线**：PX4-Autopilot `v1.17.0`（commit `d6f12ad1c4f7`，NuttX 子模块 `fb2fadf6f599`）

## 1. 背景与问题

商业闭源飞控产品需要迁移至国产 GD32H757ZMT6 平台，同时要求保留 PX4 原生飞控算法与中间件（EKF2、姿态/角速度/位置控制、Control Allocation、Commander、Navigator、uORB、WorkQueue、参数系统、MAVLink 与 QGroundControl 兼容性），并支持后续闭源商业化及上游 PX4 同步能力。

## 2. 架构决策

1. **保留 PX4 原生 NuttX + POSIX 运行模型**：不另起 FreeRTOS 中间件或重写 PX4 飞控栈，所有状态估计、控制律与任务调度直接复用 PX4 v1.17.0 原生实现。
2. **先落地 NuttX GD32H7 MCU 与板级支撑，再接入 PX4**：
   - Apache NuttX 主线当前仅支持 `gd32f4` 与 `gd32w51x`，尚无 `gd32h7` 支持（[NuttX Platforms](https://nuttx.apache.org/docs/latest/platforms/)）。
   - 兆易创新下游仓库 `GD32-MCU-IOT/gd32_nuttx`（Apache-2.0，最新提交 `a71c8d5`）已包含 `arch/arm/src/gd32h73x_75x/` 与 `boards/arm/gd32h73x_75x/gd32h759im-eval/`。
   - 因此采用**基于 PX4 锁定 NuttX 子模块（`fb2fadf6f599`）最小化移植/审计合入 `gd32h73x_75x` 驱动**的策略，禁止不经审计直接用外部主线替换 PX4 锁定的 NuttX 子模块。
3. **严格隔离平台差异与私有模块**：
   - MCU 与外设 BSP 置于 `platforms/nuttx/NuttX/nuttx/arch/arm/src/gd32h73x_75x/` 及独立补丁集；
   - 板级配置置于 `boards/gd32/h757-fc-v1/`；
   - 商业私有功能作为独立 PX4 模块隔离，不侵入 EKF2/控制器核心代码，保持上游 `v1.17.x` 合并能力。
4. **禁止寄存器照搬**：严禁将 STM32H7 寄存器偏移、IRQ 编号、AF 引脚复用或 DMAMUX 映射直接照搬至 GD32H757，所有硬件定义必须对照 GD32H737/757/759 用户手册与具体板卡原理图逐项核实。

## 3. 合规与闭源边界

- PX4-Autopilot 主体采用 **BSD-3-Clause** 许可，Apache NuttX 采用 **Apache-2.0** 许可，均允许商业闭源发行，但必须保留版权声明、许可文本及免责声明，并对 GD32 官方固件库/SDK 逐文件核查授权条款。
